## M6 执行方案（目录管理先行）

> 语法依据：`Resty/doc/http-syntax.md`

### 总目标

- 一个工作区对应一个真实目录。
- 一个集合对应一个 `.http` 文件。
- 一个请求对应 `.http` 文件中的一个请求块（主要使用 `###` 分隔）。

### 优先级调整

- 先做目录管理打底，再做工作区真实解析与执行。
- 目录管理完成后，工作区不再依赖假数据，全部来自目录下的 `.http` 文件。

### P1：目录管理完善（先做）

- 打开目录时，建立 `WorkspaceRootPath`（真实目录绝对路径）。
- 目录管理中的“打开”或双击条目，统一进入同一工作区上下文。
- 在目录管理中补充“工作区目录有效性”校验：
	- 路径不存在时提示；
	- 无可读权限时提示；
	- 可读但无 `.http` 文件时，允许进入工作区并提示“新建集合”。
- 目录管理负责提供最近目录与已管理目录的持久化入口（M6 内可先 JSON 文件落盘）。

### P2：集合=文件（工作区真实加载）

- 扫描工作区目录下所有 `.http` 文件（递归，跳过 `.git/bin/obj/node_modules`）。
- 每个 `.http` 文件映射为一个集合节点：
	- 集合名默认取文件名；
	- 保留相对路径用于唯一标识。
- 若扫描结果为空：右侧提示“当前工作区暂无集合，请新建集合”。

### P3：请求=请求块（HTTP 语法解析）

- 以 `###` 切分请求块，支持空分隔与带标题分隔。
- 识别请求头行：
	- 标准形式：`METHOD URL HTTP/x.y`；
	- GET 简写：仅 URL（默认 `GET`）。
- 识别注释与命名：
	- `# @name`、`### 标题` 作为请求显示名来源；
	- `// @no-log`、`# @timeout` 等注解先保留到模型。
- 识别 Headers 与 Body（空行分隔），支持 `< file` 形式的 Body 引用。
- 若选中集合但没有任何请求块：提示“请新建请求”。

### P4：编辑与保存（文件回写）

- 新建集合：创建新的 `.http` 文件并写入请求模板。
- 新建请求：在目标 `.http` 文件追加 `###` + 请求模板块。
- 编辑请求并保存时，按“请求块级重写”回写原文件。
- 保留原文件非请求区注释，不做全文件重排。

### P5：真实发送与历史

- 发送请求使用 Infrastructure 中真实 `HttpClient` 执行器。
- 响应结果回填 `code/time/size + body/headers/cookies`。
- 发送成功后写入历史列表；`@no-log` 请求不落历史。
- 历史记录持久化为工作区内数据文件（建议 `.resty/history.json`）。

### P6：变量与环境（按语法逐步接入）

- 首期支持：
	- 文件内变量（`@name = value`）；
	- 环境变量（`http-client.env.json` + `http-client.private.env.json`）。
- 变量优先级遵循语法文档定义（高到低）。
- 暂不支持或后续支持：脚本变量、动态变量、复杂 JSONPath。

### 验收标准（新增）

- 打开任意目录后，工作区可稳定加载对应 `.http` 文件集合。
- 集合内请求数与 `###` 分块数量一致。
- 选中请求可编辑、保存、发送并看到真实响应。
- 无集合时提示新建集合；无请求时提示新建请求。
- 发送历史可见且可持久化（遵循 `@no-log`）。

## 设计约束

- 保持无边框窗口
- 优先复用 Semi/Ursa 原生控件和样式体系
- 每个功能模块先做 ViewModel 状态，再做视图绑定
- 每个里程碑结束都可独立演示
